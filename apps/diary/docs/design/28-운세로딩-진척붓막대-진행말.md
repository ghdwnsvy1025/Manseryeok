# 28 — 오늘 화면 운세 로딩: 진척 붓 막대 + 진행 말 (캐릭터 없음)

> 먼저 `00-톤.md`(v3.28 절까지, 특히 v3.2 "로딩" 절과 v3.26 금색 원칙)를 읽는다. `frontend-design` 스킬로 작업. 출처: 사용자 요청 2026-10-23 — "로딩될 때 동적으로 원형 로딩이나 진척 바로 보이게. 캐릭터는 없어도 된다. 명언이나 진행 상황 말."
> 톤 문서와 맞춘 해석: 원형 게이지·스피너·명언은 `02`·`06`·`00`이 금지한 것이라 쓰지 않는다. 대신 **이미 허용된 로딩 붓선을 "차오르는 진척 막대"로** 바꾸고, **진행 단계를 말로** 보인다(회전 티저 문구가 아니라 실제 단계 설명). 이 두 가지는 00에 v3.29 절로 적는다.

## 왜
- 운세가 캐시에 없는 날, 오늘 화면은 바로 뜨고 운세 자리에 로딩 카드가 5~25초 보인다(기능 2026-10-23: 생성은 응답 뒤 백그라운드, `FortunePending`이 3초마다 캐시를 묻고 생기면 refresh). 지금 카드는 캐릭터 48px + "오늘 글자를 읽고 있어요" 한 줄, 정지 상태라 **멈춘 것처럼 보인다**.
- 사용자는 "일하고 있다"는 움직임과 "어디까지 왔는지"를 원한다.

## 기능이 이미 넘기는 것 (바꾸지 않는다)
- `src/components/FortunePending.tsx`(클라이언트): 폴링·`gaveUp`(25번 뒤 "불러오지 못했어요 · 다시 시도") · `ready`(캐시가 생겨 refresh 직전, 수백 ms) 상태를 갖고 `<FortuneLoading character ready />`를 그린다. 폴링 로직·액션 호출·gaveUp 분기는 손대지 않는다. JSX·className만.
- `src/app/page.tsx`는 `character`를 넘기지만 이 명세는 쓰지 않는다(무시). page.tsx는 수정하지 않는다.
- 서버는 진행률을 모른다. 파이프라인 단계(fortune/index.ts → llm.ts)는 대략: 사주 계산(<1초) → 모델이 글 씀(5~20초) → 검사·필요하면 다시 씀(0~15초) → 검수(0~5초). **진척은 경과 시간으로 추정**해 그린다(아래 표). 정확한 퍼센트가 아니므로 숫자는 쓰지 않는다.

## 수정 가능 파일
- `src/components/FortuneLoading.tsx` — 전부(클라이언트 컴포넌트로 바꿔도 됨. `character`·`ready` prop 서명은 유지).
- `src/components/FortunePending.tsx` — JSX·className만(위 참고).
- `src/app/globals.css` — `.fortune-loading*` 규칙, 필요한 keyframe.
- `docs/design/00-톤.md` — v3.28 절 아래 "v3.29" 한 단락.
- 금지: page.tsx, actions.ts, fortune/*, 다른 화면, 새 에셋 생성(기존 `divider-clean`·`brush-stroke.webp`·`gold-wash` 재사용).

## 필요한 에셋
없음. 붓획 마스크는 `public/ui/brush-stroke.webp`(나 화면 오행 붓 막대가 쓰는 것) 또는 `divider-clean.png`(현재 로딩 붓선) 중 막대에 더 맞는 것.

## 화면 구조 (운세 카드 자리, 열린 운세 카드 틀 `card-gold card-paper`, 높이는 닫힌 카드와 같게 `.fortune-loading` min-height 유지)
1. 제목 "오늘의 운세" 15px muted — 지금 그대로.
2. **진척 붓 막대**: 트랙 바탕 없음(한지 그대로). fill = 금색 면(`gold` 또는 gold-wash 질감) + 붓 가로획 마스크, 높이 10~12px, 폭 100%. 왼→오로 **차오른다**(반복 쓸기 아님). 붓 끝(오른쪽)이 갈라지는 마스크를 쓴다. 금색은 면이므로 v3.26 원칙에 맞는다.
3. **진행 말** 한 줄 15px muted(Pretendard), 막대 아래 8px. 단계가 바뀔 때 글자만 바뀐다(페이드 120ms 허용, 슬라이드·타이핑 효과 없음).
4. 캐릭터·붓선 반복 애니메이션·점 세 개·퍼센트 숫자 없음.

## 진척 추정표 (경과 시간 기준, 컴포넌트 마운트 시점부터)
| 경과 | 막대 | 진행 말 |
|---|---|---|
| 0~1.5초 | 0 → 12% | 사주를 펼치고 있어요 |
| 1.5~5초 | 12 → 30% | 오늘 간지와 맞춰 보고 있어요 |
| 5~18초 | 30 → 75% | 운세 글을 쓰고 있어요 |
| 18초~ | 75 → 92%에서 멈춤(ease-out, 더 안 감) | 글을 다듬고 있어요 |
| `ready` | → 100% (300ms) | 다 됐어요 |
| `gaveUp` | (FortunePending의 기존 오류 카드, 손대지 않음) | — |

- 구간 안에서는 선형 또는 ease-out으로 부드럽게. 구현은 `requestAnimationFrame` 또는 300ms 간격 상태 갱신 중 가벼운 쪽. 서버 렌더(첫 그림)는 0%·첫 문구.
- 같은 날 다시 열어 로딩이 또 보이면(아직 만드는 중) 0부터 다시 시작해도 된다 — 서버 시각을 모르므로.

## 모션
- 허용: 막대 차오름(width 또는 scaleX 전환), 문구 페이드 120ms, ready 때 100% 채움 300ms.
- `prefers-reduced-motion`: 전환 없이 값만 바뀐다(막대는 단계별로 툭툭 늘어남, 문구는 바로 교체).
- 그 밖의 반복 애니메이션 없음. 카드 틀·제목은 움직이지 않는다.

## 하지 않는 것
원형 스피너·원형 게이지, 명언·격언, 돌아가는 티저 문구("두근두근" 류), 퍼센트 숫자, 캐릭터 그림, 새 에셋, 인주·남색 사용, 글자에 금색, 레이아웃 높이 변화(카드 자리 높이는 닫힌 카드와 동일).

## 끝났을 때 확인
- `npx tsc --noEmit`, `npm test` 통과.
- 375px: 운영 DB 쓰기 없이 보는 방법 — 정적 하네스(명세 26·27과 같은 방식)로 `FortuneLoading`을 0초·3초·10초·20초·ready 다섯 상태로 그려 스크린샷. 막대가 카드 안쪽 폭을 넘지 않고, 문구 한 줄, 가로 스크롤 없음, 카드 높이가 닫힌 운세 카드와 같음.
