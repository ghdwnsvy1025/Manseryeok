# 29 — 오늘 화면 운세 로딩: 달이 차오른다 (명세 28을 대체)

> 먼저 `00-톤.md`(v3.29 절까지)를 읽는다. `frontend-design` 스킬로 작업. 출처: 사용자 2026-10-23 — "운세 로딩이 너무 이상해. 디자인 에셋을 만들어서라도 세련되고 로딩이 되고 있다는 느낌이 들게" → 제안 3개 중 1안 "달이 차오른다" 선택.
> 명세 28(금색 붓 막대 + 진행 말)은 막대가 카드 안에 덩그러니 있어 "반쯤 그려진 화면"처럼 보였다. 막대는 없앤다. 진행 말과 경과 시간 추정은 그대로 쓴다.

## 왜 달인가
- 앱 아이콘(2026-10-23 교체)이 한지 위 붓 한 획 초승달이다. 로딩이 같은 달이면 아이콘과 로딩이 한 물건이 되고, 초승달 → 반달 → 보름달로 **모양이 바뀌는 것 자체가 진행**이라 설명이 필요 없다.
- 톤 문서의 밤은 남색 악센트다. 먹 달 하나면 충분하고 다른 장식은 넣지 않는다.

## 기능이 넘기는 것 (바꾸지 않는다)
- `src/components/FortunePending.tsx`(클라이언트): 3초마다 캐시를 묻고 `ready`(캐시 생김, refresh 직전 수백 ms)·`gaveUp`(실패 카드)을 들고 `<FortuneLoading character ready />`를 그린다. 폴링·액션·gaveUp 분기는 손대지 않는다. JSX·className만.
- `FortuneLoading.tsx`의 `estimateProgress(elapsedSec)`(경과 초 → 0~92% 추정, 단계 번호, 진행 말)는 그대로 쓴다. `character` prop은 무시(서명 유지).
- 서버는 진행률을 모른다. 퍼센트 숫자는 보이지 않는다.

## 수정 가능 파일
- `src/components/FortuneLoading.tsx` — 전부(클라이언트 컴포넌트. prop 서명 `{ character?: string; ready?: boolean }`·`estimateProgress` export 유지).
- `src/app/globals.css` — `.fortune-loading*` 규칙·keyframe(막대 규칙은 지운다).
- `public/ui/moon-ink-disc-512.webp` — 아래 에셋을 saju-assets `copy`로 (투명 webp, 512).
- `docs/design/00-톤.md` — v3.29 절 아래 "v3.30" 한 단락(v3.29의 막대는 폐기했다고 적는다).
- 금지: page.tsx, actions.ts, fortune/*, FortunePending의 로직, 다른 화면.

## 화면 구조 (운세 카드 자리, 틀은 열린 운세 카드와 같은 `card-gold card-paper`)
```
┌──────────────────────────────────┐
│ 오늘의 운세                      │  15px muted (지금 그대로)
│                                  │
│  ◖  운세 글을 쓰고 있어요         │  달 64px + 진행 말 15px muted, 세로 가운데
│                                  │
└──────────────────────────────────┘
```
1. **먹 달 64px**: 왼쪽. 원판 그림(`moon-ink-disc-512.webp`)을 SVG `<mask>` 또는 CSS mask로 가려 초승달을 만든다 — 원판과 같은 지름의 가림 원을 오른쪽으로 비켜 두고, 진척이 오르면 가림 원이 오른쪽으로 빠져나가 달이 차오른다(0% = 왼쪽 가장자리 얇은 초승달, 50% = 왼쪽 반달, 100% = 보름달). 아이콘의 초승달과 같은 "원 빼기 원" 모양이라 아이콘과 한 물건으로 읽힌다. 가림 원의 이동은 CSS 마스크(radial-gradient 구멍)의 `mask-position` 전환 300ms linear(갱신 간격과 같아 이어져 보인다) — 구현 때 `transform`이 마스크에 안 먹어 이렇게 정했다. 가려진 부분엔 아무것도 없다(한지 그대로) — 희미한 원 윤곽·점선·후광 없음.
2. **진행 말** 15px muted, 달 오른쪽 12px, 세로 가운데. 단계가 바뀔 때 120ms 페이드 한 번(명세 28과 같음). 한 줄 말줄임.
3. 제목 "오늘의 운세"는 지금처럼 위에.
4. 막대·캐릭터·점·퍼센트 없음.

## 상태별 모습
| 상태 | 달 | 말 |
|---|---|---|
| 0~1.5초 | 0 → 12% (얇은 초승달) | 사주를 펼치고 있어요 |
| ~5초 | → 30% | 오늘 간지와 맞춰 보고 있어요 |
| ~18초 | → 75% (반달 넘김) | 운세 글을 쓰고 있어요 |
| 18초~ | → 92%에서 멈춤 | 글을 다듬고 있어요 |
| `ready` | → 100% 보름달, 300ms ease-out | 다 됐어요 |
| `gaveUp` | FortunePending의 기존 실패 카드(손대지 않음) | — |
서버 렌더(첫 그림)는 0%·첫 문구. 비율 → 가림 원 위치는 선형으로 충분하다(p=0일 때 가림 원 중심이 달 중심에서 오른쪽으로 지름의 약 10%, p=1일 때 지름 이상 빠져나감).

## 카드 높이
명세 28 구현 보고에서 로딩 카드 122px, 밤의 **닫힌** 운세 카드 171px로 달라 전환 때 자란다고 했다. 이번엔 `.fortune-loading`의 min-height를 닫힌 운세 카드 높이에 맞춘다 — 구현자가 닫힌 카드(details 닫힘, 밴드 단어·영역 칩 포함)를 다시 재서 그 값으로. 달 64px + 제목이 그 높이 안에 세로로 편하게 앉는다.

## 모션
- 허용: 가림 원 이동(차오름) 전환 300ms, 문구 페이드 120ms, ready 때 300ms ease-out.
- `prefers-reduced-motion`: 전환 없이 값만 바뀐다(달은 단계별로 툭툭 차오름).
- 반복 애니메이션·회전·숨쉬기·후광 없음. 달은 커지거나 움직이지 않는다 — 차오를 뿐.

## 하지 않는 것
막대, 스피너, 점 세 개, 퍼센트 숫자, 캐릭터, 명언, 후광·글로우, 희미한 달 윤곽선, 별, 금색·인주색 사용(달은 먹 남색만), 새 그림 생성(원판 한 장으로 끝), 레이아웃 폭 변화.
