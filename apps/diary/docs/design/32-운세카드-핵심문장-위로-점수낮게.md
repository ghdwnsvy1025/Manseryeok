# 32 — 운세 카드: 오늘의 핵심 문장을 점수 위로, 영역 신호 전부, 오늘 힘이 되는 것, "아니에요" 이유

> 먼저 `00-톤.md`(v3.35까지)를 읽는다. `frontend-design` 스킬로 작업. 출처: 2026-10-31 사용자가 ChatGPT 검토를 반영해 달라고 함. 운세 글쓰기는 v4.19로 바뀌었다(기능 쪽 끝남).

## 왜
- 지금 카드의 주인공은 "무난 5.7 / 10"이다(FortuneCard.tsx summary의 `.score-brush`, 밴드 44px·숫자 34px). 그런데 점수는 측정값이 아니라 판정 단계를 경험적 계수로 옮긴 값(core.ts "계수(가설)")이라, 소수점까지 크게 보이면 실제보다 정밀해 보인다. 같은 "무난"이 이어질 때 "또 무난이네"가 먼저 읽힌다.
- 체감 다양성은 숫자가 아니라 **오늘의 핵심 문장**에서 나와야 한다. 점수는 정직하게 그대로 두되 시각적 중요도를 낮춘다.

## 화면 구조 (닫힌 카드 = summary)
```
오늘의 운세                                   +
무난                                  ← 밴드 단어, 송명 20~22px, 단계 붓 자국(data-band) 그대로 작게
혼자 끌어안지 않는 하루                 ← fortune.headline, 송명 26~28px, 카드의 주인공 (최대 2줄)
5.7 / 10                               ← 15~17px muted tabular, 한 줄 작게 (밴드와 같은 줄 오른쪽도 가능)
[사람 ↓] [돈 ↓]                        ← 오늘 영역 칩 (지금 그대로)
```
- 펼친 본문에서는 headline을 다시 크게 쓰지 않는다(이미 위에 있다). 본문 문단부터 시작.
- 점수 숫자에 금색 글자 금지(지금 `text-gold-ink`는 유지 가능, 크기만 줄임). 붓 자국은 밴드 단어 뒤에만.

## 펼친 카드
1. 본문 문단 (그대로)
2. 내 기록으로 본 오늘 (그대로)
3. **오늘의 특징** — 기능 쪽이 `fortune.areas`를 이제 코어 신호 전부로 만든다(v4.19 visible.composeAreas: 오늘 ≤2, 이달 1, 올해 1, ↑ 먼저). 화살표 줄 그대로.
   - 그 위에 **오늘 힘이 되는 것** 칩 한 줄: `(fortune as { keywords?: { positive: string[] } }).keywords?.positive ?? fortune.core?.keywords?.positive ?? []`의 앞 3개. 없으면 줄째 없음. 띠지 칩(긍정 tone = 금빛 쪽), 제목 13px muted "오늘 힘이 되는 것".
4. 오늘 해 볼 것 (그대로)
5. 투표 — "아니에요" 뒤에 이유 버튼 셋(`.vote__reasons` > `.vote__reason`: 내용이 안 맞았어요 / 너무 뻔했어요 / 문장이 어색했어요)이 한 번 뜬다. 기존 `.vote__btn`보다 한 단계 작은 종이 띠지(높이 32px, 13~14px), 줄바꿈 허용.
6. "운세 계산 v4.19" 줄 (그대로)

## 상태
- 좋음/무난/주의 세 밴드, headline 짧은 것(10자)·긴 것(22자, 두 줄), 영역 칩 0~2개, 힘이 되는 것 0·3개.
- 옛 캐시(v4.18) 운세도 같은 필드로 그려진다(headline·areas·core.keywords 있음).
