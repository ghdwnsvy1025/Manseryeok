## 1. 사용자 여정 — 막히거나 헷갈리는 지점

### 1-1. 첫 방문 → 온보딩 → welcome → 오늘

흐름: 세션 없음 → `Booting`(뼈대) → `AnonBoot`가 익명 세션 생성 → `router.refresh()` → 프로필 없으면 `/onboarding?next=/` → 저장 → `/welcome`(실루엣 1.2초 → 팡 → 카드) → "오늘 운세 보기" → `/`.

**H-1 · 높음 · 기존 Google 사용자가 새 기기에서 자기 기록으로 돌아갈 길이 없다**
- 증거: `/login`은 "앱 안에서 여기로 오는 링크는 없고, 주소를 직접 치면 열린다"(`src/app/login/page.tsx:5`). 새 기기에서는 익명 세션이 자동으로 만들어지고(`AnonBoot.tsx:31`) 온보딩이 강제된다(`page.tsx:119`). 생년월일을 다시 넣고 설정 → "Google로 연결하기"를 눌러야 비로소 `?error=link`로 "로그인 화면의 '기존 Google 계정으로 로그인하기'를 눌러 주세요"(`settings/page.tsx:47-53`)가 나온다.
- 사용자 영향: 돌아온 사용자가 온보딩을 한 번 더 치르고, 실패 메시지를 거쳐야 자기 기록에 닿는다(Krug "클릭 수가 아니라 확신"의 정반대).
- 제안: 온보딩 머리에 글자 링크 한 줄 "이미 Google로 쓰던 분은 여기서 이어가요 → /login"(금색 아님). 설정 Google 줄에도 "기존 계정으로 로그인" 글자 링크. → **구현(기능)**.

**H-1b · 높음 · "기존 Google 계정으로 로그인하기"가 확인 없이 익명 기록을 버린다**
- 증거: `GoogleButton.tsx:47` `if (mode === "fresh") await supabase.auth.signOut();` 뒤 바로 OAuth. 설명은 버튼 아래 작은 글(`linkPrompt.ts:38` "이 기기의 기록은 이 기기에 남지 않아요")뿐, 두 번 누르기·건수 표시 없음.
- 영향: 이 기기에서 며칠 쓴 뒤 누르면 기록이 즉시 접근 불가(익명 user_id가 버려진다). 삭제 버튼은 두 번 누르기(§5)인데 같은 결과를 내는 이 버튼은 한 번이다 — 일관성(N#4)·오류 예방(N#5) 위반.
- 제안: 익명 기록이 1건 이상이면 `ClearAllButton`과 같은 두 번 누르기 + "이 기기의 기록 N건은 더 못 봐요" 문구. → **구현(기능)**.

**M-3 · 중간 · 5초 뒤 "준비하고 있어요 · 다시 시도"가 원인을 말하지 않는다**
- 증거: `Booting.tsx:26-27`, `RetryButton.tsx:10`(새로고침). `AnonBoot.tsx:33-35` 실패는 `console.error`만.
- 영향: 오프라인·차단된 Supabase 등 어떤 상황이든 같은 문장. N#9(오류 진단) 미달.
- 제안: `navigator.onLine`이 false면 "인터넷 연결을 확인해 주세요", 그 외 "시작하지 못했어요. 다시 시도해 주세요"로 둘로 나누고, 뼈대 5초 → 3초. → **구현(기능 + 문구)**.

**M-4 · 중간 · 온보딩 성별이 필수인데 표시가 없고, 안 고르면 제출 뒤에야 안다**

- 제안: 라벨 옆 "(운세 계산에 필요해요)" 한 줄 또는 제출 전 클라이언트 검사. → **구현**.

- 증거: `ProfileForm.tsx:161-163`. 제안: "1995 / 05 / 15"로 통일. → **구현**.

**L-2 · 낮음 · "처음 한 번만"(온보딩 eyebrow)과 설정의 "고치기"가 어긋난다**
- 증거: `onboarding/page.tsx:24`. 고칠 수 있으니 "처음 한 번만"은 약한 거짓. 제안: "시작하기 전에" 또는 삭제. → **구현(문구)**.

**L-3 · 낮음 · welcome 설명 줄에 기호 `=`**

- 문구 "기기를 바꿔도 남게 Google로 연결해요 / 지금 기록은 이 기기에만 묶여 있어요. 연결하면 어디서든 이어서 써요." — 사실이고 담백하다. 다만 "이 기기에만 묶여 있어요"는 브라우저 데이터 삭제·앱 삭제 시 사라진다는 **진짜 위험을 말하지 않는다**(§5). 한 줄 추가 권장: "브라우저 데이터를 지우면 기록도 사라져요."
- 설정의 "아직 이 기기에만 있는 기록이에요"도 같다.

**오류 문구**: 세 요소(무엇·왜·어떻게) 중 "왜"가 빠진 곳 — "로그인하지 못했어요. 다시 눌러 주세요"(`login/page.tsx:29`), "준비하고 있어요. 잠시 뒤 다시 눌러 주세요"(`actions.ts:33`), "저장하지 못했어요. 잠시 뒤…"(×3). 네트워크/권한 구분이 가능한 곳부터 이유를 넣는다. 온보딩 검증 문구(`profile.ts:96-121`)는 필드별로 정확해 모범.

## 6. 잘 된 점

1. **입력 보존과 오류 위치**: 온보딩·쓰기 폼이 `onSubmit`으로 제출해 서버 오류 뒤에도 내용이 남고, 오류를 해당 묶음 바로 아래 `role="alert"`로 둔다(`ProfileForm.tsx:77-82`). 행복도를 안 고르고 저장하면 그 자리로 스크롤·포커스한다(`EntryForm.tsx:80-84`).
2. **파괴 동작의 일관된 확인 방식**: 두 번 누르기 + 5초 리셋 + 라벨이 조건을 말한다. 모달 없이 톤을 지켰다.
3. **로딩 설계**: 탭 전환은 이전 화면 유지 + 점 하나, 운세 자리는 높이 고정 + 캐릭터 한 장, 실패 시 재시도. "스피너 금지"를 지키면서 N#1을 만족한다.
4. **접근성 기본기**: `details/summary`로 JS 없이 열림, 달력 칸 `button + aria-pressed + aria-label`, 메달 이미지 alt, 영역 화살표에 sr-only 단어, 모든 모션에 reduced-motion 분기, `:focus-visible` 금색 외곽선.
5. **톤의 규율**: 색 토큰이 키트 측정값에서 오고, 길흉을 색으로 말하지 않는 규칙·가운뎃점 금지·금색 면 하나가 실제 코드에서 지켜진다. 기계 검사(`impeccable detect`)에서 명세된 예외 2건 외 지적 0.
