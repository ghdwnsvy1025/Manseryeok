# 이용 통계 (PostHog) — 사주 일기

2026-10-22. 사람들이 어떤 버튼을 누르고 어떻게 움직이는지 본다. 운영 숫자 화면(`/stats?key=`, `lib/metrics.ts`)은 DB에서 세는 합계이고, 이건 브라우저에서 보내는 행동 기록이다. 둘은 서로 보완한다.

## 켜는 법

1. PostHog(us.i.posthog.com)에서 **사주 일기용 새 프로젝트**를 만든다 (바이럴과 섞지 않는다).
2. 프로젝트의 `phc_…` 키를 `.env.local`과 Vercel 환경변수의 `NEXT_PUBLIC_POSTHOG_KEY`에 넣는다. 호스트가 us가 아니면 `NEXT_PUBLIC_POSTHOG_HOST`.
3. 끝. 키가 비어 있으면 아무것도 보내지 않는다.

로컬(`localhost`)에서는 키가 있어도 보내지 않고 개발자 도구 콘솔에 `[track] 이벤트 {속성}`으로 찍는다 (console.debug — 콘솔 레벨을 "Verbose"까지 켜야 보인다). 주소에 `?ph=1`을 붙이면 `env=dev`를 달고 실제로 보낸다.

## 원칙 (바이럴 `analytics.js`와 같다)

- **이름 붙인 이벤트만.** 자동 수집(autocapture)·히트맵·죽은 클릭·성능·예외·세션 녹화·서베이 전부 코드에서 끈다 (PostHog 프로젝트 설정만 믿으면 켜져서 들어온다).
- **생년월일·태어난 시각·이름·일기 본문은 보내지 않는다.** 속성 이름이 `/year|month|day|hour|minute|birth|lunar_date|생년|생일|출생/i`에 걸리면 보내기 직전에 지운다 (`lib/analytics/core.ts` `BLOCK`, 모든 이벤트에 `sanitize_properties`로 한 번 더). "today"도 day에 걸리므로 날짜 종류는 `when`으로 적는다.
- **사용자 ID는 해시.** 로그인한(Google) 사용자만 Supabase user id의 SHA-256 앞 16자로 `identify`. 익명 세션은 식별하지 않는다(`person_profiles: identified_only` — 사람 프로필은 식별된 사람만 만들어져 비용이 낮다). 로그아웃하면 `reset`. 익명 기록에 Google을 붙이면 같은 user id라 그 기기의 이전 이벤트가 그 사람으로 합쳐진다.
- **주소의 `key=`는 지운다** — 운영 숫자 화면의 비밀이 pageview 주소로 새지 않게.
- 쿠키 대신 `localStorage`. 전역 속성 `app: "diary"`, `env: prod|dev`. 바이럴 공유 링크의 `?src=`·`?from=` 꼬리표는 첫 유입 속성으로 남는다.

## 코드 위치

| 파일 | 역할 |
|---|---|
| `src/lib/analytics/core.ts` | 순수 함수: BLOCK, 속성 정리, 주소 비밀 제거, 해시, 세션 변화 판단. 테스트 `test/analytics.test.ts` |
| `src/lib/analytics/index.ts` | `track(event, props)`, `trackPageview`, `syncAuth`(identify/reset/login_success). posthog-js 초기화 옵션 |
| `src/components/Analytics.tsx` | layout에 한 번. 경로·쿼리가 바뀔 때마다 `$pageview`, Supabase 세션 변화 → `syncAuth` |
| `src/components/track/*` | 서버 컴포넌트 화면용 작은 클라이언트 조각: `TrackOnMount`, `TrackedLink`, `FortuneViewTrack`, `OnboardingDoneTrack` |

쓰는 법: 클라이언트 컴포넌트에서 `import { track } from "@/lib/analytics"; track("share_click", { channel: "kakao" })`. 서버 컴포넌트 화면은 `<TrackOnMount event="…" />` 또는 `<TrackedLink event="…" href="…">`.

## 보는 법 — 퍼널 3개

PostHog → Product analytics → New insight → **Funnel**. 전환 기간은 기본 14일, 세 번째만 7일.

1. **방문 → 가입**: `$pageview` → `onboarding_done` (`mode = first`). 익명 세션은 식별하지 않지만 PostHog의 기기 ID가 localStorage에 남아 같은 기기 안에서는 이어진다. 중간 단계로 `onboarding_step (step = date)`를 넣으면 폼을 열고 어디서 떠나는지 보인다.
2. **가입 → 첫 일기**: `onboarding_done` → `diary_saved`. 중간에 `welcome_start_click`, `fortune_view`, `diary_write_open`을 넣으면 운세는 봤는데 안 쓰는지, 폼은 열었는데 저장을 안 하는지가 갈린다.
3. **첫 일기 → 7일 안에 두 번째 일기**: `diary_saved` → `diary_saved`(같은 이벤트 두 번), 전환 기간 **7일**. 재방문의 핵심 숫자. `/stats`의 "7일째 다시 옴"과 나란히 본다.

그 밖에 자주 볼 것: `fortune_feedback`에서 `v = 1` 비율(운세가 맞는다고 느끼는가), `diary_save_blocked`(행복도 안내가 보이는가), `login_start → login_success`(Google 연결이 끝까지 가는가), `settings_push_toggle result` 분포.
